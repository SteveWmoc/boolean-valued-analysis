## Scope and documentation check

The release contains the completed Hilbert-free M024 arithmetic on internal
reals/Boolean spectral families and the M025 definite-set and internal
function correspondence from Takeuti §1.4. M025 provides both directions
of the **general** function correspondence, including unique reverse
recovery to top-valued target members; the ordinary `InternalReal` sequence
specialization currently has **forward** realization only.

The README, changelog, release notes and release checklist record these
limits without claiming the upper-cut closure needed for real-typed
reverse recovery, M026 operator realization, or M027 convergence.

The README and citation metadata use Zenodo concept DOI
`10.5281/zenodo.22696492`, never the first release's immutable v0.1.1
DOI `10.5281/zenodo.22696493` as an identifier for v0.2.0. No
v0.2.0-specific DOI or release date is fabricated before publication.

## Housekeeping and QA

- The existing `.gitignore` excludes Lake's build tree.
- The root library already exports every M024 and M025 public module.
- Pinned CI rejects unfinished proofs, checks public-module exports,
  builds and lints, audits dependencies against the allowed axiom set
  `propext`, `Classical.choice`, `Quot.sound`, and compiles
  milestone and documentation probes.
- `scripts/check_release_metadata.py` replaces the previous inline
  CI-only metadata check with a locally reusable preflight for the
  release-pair match, manifest revisions, project/citation versions,
  release notes and changelog, and the concept DOI badge.
- `CONTRIBUTING.md` documents the local preflight, cache and fail-fast
  probe workflow. The current-state stable release note in
  `docs/tau-ceti/README.md` is updated.
- Historical audit reports retain the versions and findings that were
  accurate when those audits were performed.

The separate architecture audit deliberately substitutes Tau Ceti's current
Lean and Mathlib snapshot; it is a cross-version compatibility check and
**does not** change the release lockfile.

## Validation and publication boundary

The PR is release-ready only when pinned CI and the independent
architecture audit are green on its **final commit**. The pinned CI also
must pass on the `main` commit selected for the GitHub release.

The preparation PR does **not** create the Git tag, GitHub release, or
Zenodo archive. Use
[the release checklist](../releases/RELEASE_CHECKLIST.md) to create the
`v0.2.0` release only from the verified commit, confirm Zenodo's new
version-specific archive, and retain the concept DOI in long-lived
project metadata.
