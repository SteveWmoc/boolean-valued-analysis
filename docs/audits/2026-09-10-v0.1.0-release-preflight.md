# v0.1.0 release preflight audit

**Date:** 2026-09-10  
**Release target:** `v0.1.0`  
**Source baseline:** `main` at `32a7de371d14f4311a352ab999fa9b907b1ecc42` (M023 squash merge)  
**Audit PR:** #61

## Purpose

This audit prepares the repository for its first tagged release. It is a
housekeeping and QA pass only: no M024 mathematics is introduced here.

The preflight has four goals:

1. move the reproducible project environment to the latest stable matching
   Lean/Mathlib release pair;
2. reconcile current-state documentation with the completed M023 public API;
3. tighten automated release-facing QA without changing mathematical semantics;
4. leave an explicit record of what was checked before a tag or GitHub Release
   is created.

## Stable toolchain repin

The GitHub release metadata for Lean and Mathlib was checked on 2026-09-10.

- Lean `v4.33.1`;
- Mathlib `v4.33.1`;

  `0df444a360eaa60ab8c11dca51a86af692955474`.

- `lake-manifest.json` to the exact dependency closure of that Mathlib release.

The committed manifest remains the reproducibility record; the human-readable
Lake input remains the stable Mathlib tag.

## Release metadata

The project version was already consistently `0.1.0` in both:

- `lakefile.toml`;

release-prep branch was created, stale development branches had already been
removed and protected `main` was the only branch. During this audit the only

## Documentation reconciliation

Current-state documentation is updated through M023:

- `README.md` now describes the Hilbert-free Boolean spectral-family layer,
  both directions of the internal-real/spectral-family correspondence, and the
  packaged equivalence `InternalReal 𝔹 ≃ SpectralFamily 𝔹`;
- the repository-layout table includes `SetTheory.SpectralFamily` and
  `SetTheory.SpectralFamilyCorrespondence`;
- the README and `ROADMAP.md` both identify M024, rather than M023, as the next
  milestone;
- `ROADMAP.md` now contains an explicit M023 completion section;
- the root `BooleanValuedAnalysis.lean` module documentation records M023;
- `docs/tau-ceti/README.md` identifies `v4.33.1` as this repository's current
  stable Lean/Mathlib release pair.

Historical milestone and audit documents are deliberately not rewritten merely
because they mention Lean/Mathlib `v4.32.1`. Those statements record the actual
environment in which the corresponding work or compatibility experiment was
performed and remain historically correct.

## Automated QA tightened

Pinned CI retains the existing release-critical checks:

- reject `sorry` and `admit` in public code, acceptance files, and executable
  documentation;
- verify that every public `BooleanValuedAnalysis/**/*.lean` module is exported
  by `BooleanValuedAnalysis.lean`;
- build the public library;
- run project linting;
- compile every `Audit/M*Acceptance.lean` milestone suite;
- compile every Lean file under `docs/`.

This preflight additionally:

- removes the obsolete documentation-probe log artifact upload left from an
  earlier debugging phase;
- checks that the Lean and Mathlib stable release tags agree;
- checks that the Mathlib manifest `inputRev` agrees with `lakefile.toml`;
- checks that `lakefile.toml` and `CITATION.cff` carry the same project version;
- enables `leanprover/lean-action`'s dependency-axiom audit with the project's
  explicit metatheoretic allow-list:
  `propext`, `Classical.choice`, and `Quot.sound`.

The axiom allow-list is not a claim that every theorem depends on all three. It
is the release-wide set of known foundational dependencies permitted by the
current project architecture; any additional unexpected axiom dependency makes
CI fail.

## Manual repository QA

The preflight inspection also checked:

  repository search results;
- `.gitignore` excludes Lake's `.lake/` build tree;
- `CITATION.cff` names the repository and Apache-2.0 license and carries project
  version `0.1.0`;
- the M023 completion record and `Audit/M023Acceptance.lean` are present;
- the M023 release-facing documentation changes are targeted rather than a
  rewrite of earlier milestone history.

## Validation policy

PR #61 is release-ready only after its final head passes both validation tracks:

1. pinned CI in the repinned Lean/Mathlib `v4.33.1` environment, including the
   metadata and axiom audits plus all M001–M023 acceptance suites and
   documentation probes;
2. the live Tau Ceti architecture audit, which independently builds and tests
   the same public API against Tau Ceti's current Lean/Mathlib environment.

The GitHub check results on the final PR head are the authoritative execution
record; they are intentionally not copied as mutable status text into this
historical audit document.

## Release boundary

This preflight does **not**:

- create a Git tag;
- create a GitHub Release;
- begin M024;
- alter the mathematical meaning of the M001–M023 APIs;
- rewrite historical environment records.

Once PR #61 is reviewed, squash-merged, and its merge commit is green on `main`,
the repository is prepared for creation of the `v0.1.0` release from that
verified `main` commit.
